# dsh-duplicate-file-check

> 2026-11-06 重构：面板改为分组折叠，6 个任务各自独立（状态/进度/开始按钮），
> 完全一致校验新增「严格（逐字节）」模式；新增随机文件名、按大小移动、按时长移动三个批量改名任务。
> 抓帧任务会先排除完全一致的文件再统计时长。
 重复文件查重（DSH 插件）。两种筛法，对应主人 Java 项目 `D:\workspace\rename` 里 `simpleCheckAndDelete` 与 `checkByDuration` 的思路，并各修了一处：  ## 一、完全重复文件  1. 递归列出所有来源目录的文件，**先按大小分组**，只处理「同大小、数量 > 1」的组。 2. 组内每个文件取**头 / 中 / 尾各 100KB** 做字节比对（不是只取文件头）。    - 原 Java 版只查头 100KB，且小文件读满会报错；这里对 `size < 300KB` 的文件自适应成三等分，不会越界。    - 用 Buffer 原生字节比较，不经过字符串编码，避免任何字符集歧义。 3. 三处都相同才算重复。按组列出，并标出「保留」的那一个（组内 mtime 最早、路径字典序最前）。  改进了原版：抽样从 1 处变 3 处，误判率下降，成本仍只是每文件 300KB 读。  ## 二、视频抓帧（疑似重复）  1. 只看 `.mp4`。 2. 用 ffprobe 读时长（毫秒），按**时长容差**（可配，默认 100ms）排序后贪心分组。 3. 组内**数量 > 1** 才继续（只要不唯一就算疑似）。 4. 每段视频抓**前 10 秒、每秒 1 帧**，缩成 16×16 灰度；组内两两逐帧算平均绝对差，相似度 ≥ 阈值（默认 0.9）即判为同一段视频。    - 这样能覆盖「转码后字节不同、内容相同」的情况。  ## 参数  - 来源目录：可多个，添加后自动保存。 - 疑似重复输出目录：自动保存、自动创建。 - 时长容差（ms）、抓帧相似度（0.1–1）。 - 配置落在 `~/.dsh/duplicate-file-check.json`。  ## 两个动作  - **删除完全重复文件**：每组只保留一个，其余删除。删除前有确认框，失败会逐条报。 - **移动重复文件**：把疑似视频组里的文件移动到输出目录，重命名为 `1xxxxx.mp4`，从 100000 起、按输出目录里已有编号续号，避免覆盖。  ## 注意  - 两个写操作都只作用于「最近一次扫描结果」，不会重复执行同一批。 - 扫描是异步的，面板每 1.5 秒轮询进度；扫描中写按钮是禁用的。 - 视频模式只要求「组内 > 1」：只要时长相近的两个视频被抓帧判为相似，就会进结果。  ## 三、批量改后缀  把来源目录里所有 `.<原后缀>` 的文件改成 `.<新后缀>`（大小写不敏感，只改扩展名、不动内容）。  - 「预览」先给数字：匹配几个、可改几个、同名冲突几个。 - 「执行改名」有确认框；目标文件已存在时**跳过**，不覆盖。 - 后缀只允许 1–16 位字母数字，防止写出 `../` 这类路径片段。  ## 并发与强制停止  - 扫描全程有界并发：`concurrency` 配置项（0 = 自动，按 CPU 核数、上限 8；可手填 1–32）。   - 目录遍历后，stat → 抽样比对 → ffprobe → 抓帧 各阶段都是并发执行。   - 抓帧/ffprobe 是子进程，并发上限单独收在 8 以内，避免把机器打满。 - **强制停止**：扫描、删除、移动、改名执行中都可以点「强制停止」，服务端立刻置停止标志并 SIGKILL 所有在跑的子进程（ffprobe/ffmpeg），各循环在下一个检查点退出，状态显示「已停止」。 - 「停止」只终止正在进行的操作，不会回滚已经完成的删除/移动/改名——已做的事照实算数。
