# dsh-duplicate-file-check

DSH（DeepSeek Harness）的重复文件 / 视频整理插件（面板与侧边栏显示为「小视频整理」）：查重、抓帧比对、批量改名、按大小或时长重命名并移动、把 MOV/AVI/WMV 统一转成 MP4。

面板按任务分组折叠，每个任务都有独立的开始按钮、进度和状态；同一时刻只允许一个任务在跑。

## 九个任务

| 任务 | 做什么 | 处理对象 |
| --- | --- | --- |
| 完全一致文件校验 | 先按大小分组，再抽样（头/中/尾各 100KB）或逐字节全量比对，列出可删除的多余副本 | 来源目录里的全部文件 |
| 抓帧疑似重复校验_时长匹配 | 先排除完全一致的文件，按时长分组，比对前 N 秒画面相似度（旧算法，完全保留） | 来源目录里的 MP4 |
| 抓帧疑似重复校验_忽略片头 | 前缀帧级多候选匹配，支持片头错位与重复片段（独立模块与独立配置） | 来源目录里的 MP4 |
| 复位文件 | 按记录文件（分组目录或目标目录根部的 _dupfc_restore.json）把文件搬回原目录；已删除跳过、原目录不存在报错；记录外的文件 UUID 改名移入 resetFail | 两个抓帧模块 + 按大小/按时长/统一编码 |
| 批量改后缀 | 只改扩展名（如 dat→mp4），不动内容，同名目标自动跳过 | 来源目录里的指定后缀文件 |
| 随机文件名 | 改名为 UUID，后缀不变 | 来源目录里的指定后缀文件 |
| 按文件大小重命名并移动 | 从小到大排序，重命名为 100000 起的序号并移动到目标目录 | 来源目录里的指定后缀文件 |
| 按视频长度重命名并移动 | 按时长从短到长排序，重命名为 100000 起的序号并移动到目标目录 | 来源目录里的指定后缀视频 |
| 删除空文件夹 | 递归检查子目录，里面没有任何文件就删除（先深后浅，父目录变空也会删；跳过 .git/node_modules 等，保留输出目录） | 来源目录下的所有子目录 |
| 统一编码 | 按文件头识别 MOV/AVI/WMV，移动到对比目录并转成同名 MP4 | 来源目录里的 MOV/AVI/WMV |

## 完全一致校验

- 先按文件大小分组，只处理「同大小、数量 > 1」的组。
- 快速模式取头/中/尾各 100KB 比对；严格模式逐字节全量比对（慢但绝对可靠）。
- 「删除完全一致文件」每组保留最早的一个，其余删除，不可撤销。

## 抓帧疑似重复

- 仅处理 MP4；先排除完全一致的文件，再按时长分组（容差可配，默认 100ms）。
- 抓帧时长可配置：默认 10 秒、上限 120 秒；抓帧频率默认每秒 2 帧（1–5 可调）；只比对每个视频的前 N 秒。
- 时长容差默认 100ms；完全一致的文件先被排除，不进入抓帧阶段。
- 「移动疑似重复」把检测出的疑似重复文件**整组**移到输出目录（2 个及以上算一组，不做取舍），按 `1xxxxx.mp4` 递增重命名，方便人工确认。
- 输出目录不能等于/位于来源目录内部，也不能是盘符根目录；目标已存在时整组失败，不会覆盖。

## 按大小 / 按时长重命名并移动

- 排序依据：文件大小，或视频真实时长（ffprobe 读取）。
- 序号从 100000 起，目标目录已有编号时自动续号，不覆盖。
- 目标目录不能等于或在来源目录内部，否则直接拒绝——避免下次运行把结果再搬一遍。
- 搬移：同盘 rename，跨盘复制+删除；并发执行（见下）。

## 统一编码（MOV / AVI / WMV → MP4）

- **按文件头判定**，不看扩展名：MOV 认 `ftyp` + `qt  `，AVI 认 `RIFF....AVI `，WMV 认 ASF 头。改错后缀的文件也能认出来；本来就是 MP4 的跳过。
- 命中后先移动到「对比目录」，再转成同名 MP4（`clip.avi` → `clip.mp4`）；同名自动加 `(1)`、`(2)`，绝不覆盖。
- 源文件本来就叫 `.mp4` 时，原件进 `对比目录\original\`，避免转码结果把原件覆盖掉。
- 转码参数对齐原片：分辨率、帧率、视频码率（含 maxrate/bufsize）、音频取样率、声道数、音频码率；视频 H.264 + yuv420p，音频 AAC，`+faststart`。
- **保留原文件**默认勾选。取消勾选时，只有转码成功且校验通过的原件才会删除。
- 智能直通（默认开）：源本来就是 H.264 + AAC 且非 HDR → 只换容器，秒级完成、零画质损失。
- 编码器：x264（默认）/ NVIDIA NVENC / Intel QSV / AMD AMF，运行时探测；硬件编码器失败会自动退回 x264 重试一次。
- HDR：强制 8bit（默认）/ 色调映射到 SDR / 保留 HDR（HEVC）。色调映射需要 zscale 可用，会先实测，不可用时降级并写日志。

## 并发

面板最上方「来源目录」里的「并发数」对所有任务生效，`0` 表示自动：

| 任务 | 取值 | 说明 |
| --- | --- | --- |
| 完全一致校验 | 配置值（自动 2–8） | 并行读文件头/中/尾或全量比对 |
| 抓帧疑似重复 | 配置值（自动 2–8） | 并行抽帧比对 |
| 按大小 / 按时长 | 读大小/时长 ≤16，搬移 ≤8 | 读时长是瓶颈；搬移同盘 rename、跨盘复制+删除 |
| 统一编码 | 扫文件头 ≤16，转码 ≤4 | 转码受 NVENC 并发会话数与 CPU 限制 |

并发下的安全保证：命名用内存占位，两个 worker 不会抢同一个文件名；原件与成品分开存放；失败互不影响。

## 重扫描的独立 worker

- 「抓帧疑似重复校验_时长匹配」「抓帧疑似重复校验_忽略片头」的抓帧、指纹、候选帧比对在独立 Node 子进程里跑；DSH 插件进程只负责配置、进度转发、停止和回收。
- worker 默认堆上限 2048MB（`DFC_WORKER_HEAP_MB`），父进程按 worker RSS 的硬阈值 3072MB（`DFC_WORKER_MEM_MB`）监控；超限只杀 worker 并把任务标为失败，不拖死 DSH。
- 停止、插件卸载、HMR 重载都会用 `taskkill /T /F` 杀 worker 整棵树；worker 的 stdout/stderr 写入任务日志，不静默丢弃。
- 移动、复位、`_dupfc_restore.json` / `.jsonl` 记录仍由插件进程写，行为与旧版一致；worker 只返回扫描结果。

## 指纹缓存

- 默认开启，只服务「抓帧疑似重复校验_忽略片头」；「时长匹配」每次现抓现用，不读也不写指纹缓存。缓存按「目录 + 文件绝对路径 + 大小 + 算法 profile」查 SQLite；同一路径且大小一致时直接复用已抓帧指纹，跳过 ffmpeg。数据库只保留路径、大小和指纹，不保存修改时间。
- profile 只包含算法版本、抓帧秒数、fps、前缀帧规则和帧格式，不包含判定阈值；改阈值不会让整库缓存失效。
- 默认数据库 `%LOCALAPPDATA%\dupfc\fingerprints.db`，可在面板「指纹缓存」里改成其他路径（不要放在 DSH 用户目录）。
- 「批量改后缀」「随机文件名」「按大小移动」「按时长移动」各有「同步指纹记录」勾选，默认关闭；开启后文件改名/移动会同步更新缓存路径。
- 「清理无效文件指纹记录」删除文件已不存在、大小变化、profile 过期，以及灰度帧/`band_luma`/`band_dhash` 索引不完整的记录；父目录离线时整目录跳过，不会把离线盘缓存清空。修改时间变化不会删除记录。
- 「强制清空所有指纹缓存」清空 SQLite 中所有 profile 的记录，不动任何视频文件；按钮需二次确认。
- 「忽略片头」抓帧时新指纹先进入异步写队列，按小批量后台写入 SQLite，不阻塞抓帧/比对主循环；扫描结束或停止前会 drain。收尾发现写入条数少于抓帧视频数时，会按内存中的待写行全量补写一次；仍失败才只记日志，不影响扫描结果。
- 「忽略片头」每轮完整扫描都会按当前抓帧结果重建该 profile 的 `band_luma`/`band_dhash`；不会因为 `band_luma` 已有行就跳过某个视频，避免“luma 写成功、band 写失败”后半成品索引永久缺失。扫描中途停止时已写入的批次保留，下次扫描继续重建。
- 命中缓存前会自检：实际帧数少于「min(抓帧秒数, 视频时长) × fps」的 80%、缺少 `band_luma`、非纯色帧存在但缺少 `band_dhash`、或 BLOB/`intro_n` 不一致时，删除该文件的指纹和倒排记录并重新抓帧。pHash 没有独立表，由灰度帧派生，BLOB 可解码即保证可计算。
- 数据库写入失败只记日志，不影响扫描/移动/复位；停止或 worker 崩溃时不会把未完成目录的记录当成有效缓存。
- 对比阶段有独立进度（`逐帧相似匹配`、done/total）和日志；A/B 只按后序号单向比较，已淘汰完的 B 不再重复建候选；活跃候选过多时按上限截断并记日志。

## 日志

- 默认目录 `~/dupfc/logs`（Windows 的 `%USERPROFILE%\dupfc\logs`），固定 3 个文件：`dupfc-1.log`、`dupfc-2.log`、`dupfc-3.log`；可用 `DFC_LOG_DIR` 改目录。
- 每次 DSH 启动（插件加载）时，选择 mtime 最旧的一个槽位清空并写入；连续启动按 1→2→3→1 轮换，始终只保留最近 3 次启动。
- 记录启动配置、任务开始/结束/耗时、每个阶段日志、worker 启动/退出/超内存、异常 stack、停止请求、鉴权拒绝与路由未捕获异常。
- 日志写入是旁路：磁盘满、权限不足只打 `console.error`，不会让扫描/移动任务失败。

## 本机接口鉴权

- 面板首次带 `x-dupfc-ui: 1` 请求 `GET /dupfc/api/config` 时，宿主返回 `X-Dupfc-Bootstrap` 响应头供面板保存到内存，同时下发 `dupfc_session` Cookie（HttpOnly、SameSite=Strict）；配置 JSON 和 `/status` 都不返回 token。
- 写接口优先用 `x-dupfc-token`，Cookie 作兜底；只读统计接口不要求 token。显式传了错误 token 时不会被 Cookie 放行。
- 这是本机回环接口的会话防护，不是操作系统级隔离：同一用户下的本机进程仍可能获取并使用该 Cookie。不要把接口暴露到局域网或公网。

## 来源目录与目标目录

- 不存在的来源目录会在读取/保存配置时自动剔除，面板不会留下僵尸条目。
- 来源目录可以互相嵌套或重复配置，同一个文件只处理一次（自动去重并记日志）。
- 目标目录不存在会自动创建（只要上级目录存在）。
- 目标目录不能等于或在来源目录内部。

## 失败与停止

- 失败：原件移到 `对比目录\fail\`，日志与结果里逐条写明原因；权限类错误会提示检查 ffmpeg/ffprobe 所在目录权限。
- 停止：结束在跑的子进程，未完成的文件放回来源目录并记为「停止」，不计入失败；已完成的转换不回滚。

## 边界处理

- **可变帧率**：`avg_frame_rate` 与 `r_frame_rate` 差值 <1% 才按恒定帧率处理，否则 `-fps_mode passthrough`。
- **码率缺失**：用 `体积×8/时长 − 音频码率` 估算；估不出用 CRF 18。
- **多音轨与元数据**：`-map 0:a?` 保留全部音轨，`-map_metadata 0` 保留元数据。
- **旋转**：读 Display Matrix / rotate 标签，90°/270° 交换宽高，竖拍不压扁。
- **空间预检**：按总大小 ×1.2 估算，目标盘不够提前报错。
- **输出校验**：先写 `<名字>.mp4.part`，校验非空、可解析、时长误差 ≤ max(2s, 2%)，通过后才改名；失败清理半成品。
- **盘符根来源**：来源是 `D:\` 时，目标在其内部同样会被拒绝。

## 安装

```bash
dsh plugin install dsh-duplicate-file-check
```

或在 DSH 配置文件的 bundles 里加入本包。

环境要求：
- Node.js 22.5+（指纹缓存使用内置 `node:sqlite`）。
- DSH `>=0.2.0-rc.2`。
- ffmpeg / ffprobe：已声明可选依赖 `@ffmpeg-installer/ffmpeg`、`@ffprobe-installer/ffprobe`，npm 安装时会自动准备对应平台二进制；也可用 `DFC_FFMPEG_PATH` / `DFC_FFPROBE_PATH`（或 `FFMPEG_PATH` / `FFPROBE_PATH`）指定已有程序，插件目录下的 `.bin` 作为回退。
- 若 npm 安装时跳过了可选依赖，抓帧/统一编码会提示找不到 ffmpeg；设置上面的环境变量即可。

### 首次安装会自动准备什么

- **ffmpeg / ffprobe**：`optionalDependencies` 会在 `npm install` 时按当前平台自动安装 `@ffmpeg-installer/ffmpeg` 与 `@ffprobe-installer/ffprobe`，不需要用户手动下载；插件按“环境变量 → optional dependency → 插件 `.bin` → PATH”的顺序查找。
- **SQLite 表与索引**：第一次扫描（或打开指纹统计）时自动创建数据库目录、`fingerprints` 表、`idx_fp_dir` / `idx_fp_profile` 索引，以及持久指纹索引 `band_luma`（帧均值，服务 MAD 召回）、`band_dhash`（dHash 8×8 的 8bit band，服务哈希召回）、`idx_band_luma_lookup` / `idx_band_dhash_lookup`，并设置 `PRAGMA user_version=5`；旧版表结构会自动重建，不需要手工建表或执行 SQL。
- **数据库路径**：默认 `%LOCALAPPDATA%\dupfc\fingerprints.db`；面板里可改到任意可写目录（不要放到 DSH 用户目录）。
- **依赖自检**：面板「指纹缓存」会显示 ffmpeg / ffprobe / `node:sqlite` 是否就绪；启动日志也会写一行 `依赖检查：...`。缺少 ffmpeg 时抓帧任务会明确报错，不会静默失败；缺少 `node:sqlite`（Node <22.5）时只禁用指纹缓存，完全一致校验等任务仍可用。
- **不需要**额外安装数据库服务、SQLite 客户端或创建 Windows 服务/计划任务；`node:sqlite` 是进程内嵌入式数据库。

如果安装时用了 `npm install --omit=optional`，重新执行一次普通 `npm install` 即可补齐 ffmpeg/ffprobe；也可以设置 `DFC_FFMPEG_PATH` / `DFC_FFPROBE_PATH` 指向已有二进制。

## 删除空文件夹

- 递归扫描来源目录下的每个子目录；某个目录里没有任何文件（也不含还有文件的子目录）就删掉它。
- 先删深层再删父目录，`a/b` 删掉后 `a` 变空也会被删。
- 来源目录本身不删；符号链接与联接点（junction）不进入、不删除；`.git`、`node_modules`、`$RECYCLE.BIN`、`System Volume Information` 等目录跳过；所有输出/目标/工作目录即使为空也保留；最大递归深度 64。
- 结果统计：扫描 N 个子目录、删除 M 个、失败 K 个（被占用或无权限的会列出原因）。

## 抓帧疑似重复校验_忽略片头

- 独立模块：抓帧时长默认 40 秒（1–60，只抓前缀）、抓帧频率 1–5、片头容差 0–20 秒、失败容忍帧数默认 8（1–100）、失败清零所需连续成功帧数默认 15（1–300）、输出目录；并发数用「来源目录」里的公共设置。
- 比对方式：每条视频只抓前 N 秒；先裁掉开头连续纯色帧，再把每一帧的 16×16 灰度均值写入 `band_luma`，把非纯色帧的 dHash 8×8 切成 8 个 8bit band 写入 `band_dhash`，都按稳定的 `fp_id`（`fingerprints` rowid）持久化。匹配时先按 `mean±(MAD上限+1)` 查 `band_luma` 召回候选，再用 `viMad` 精确判定；MAD 不中的非纯色帧才查 `band_dhash` 做哈希分支（`dHash≤阈值` 且 `pHash≤阈值`）。纯色帧只走 MAD，不进入哈希分支。每个 B 最多保留 4 个候选起点；候选按游标逐帧推进，允许 ±1 邻帧和 1 帧缺口；B 尾部先结束后，剩余 A 帧不再计失败。失败也推进游标并累计失败；只有之后连续成功达到「失败清零所需连续成功帧数」才把失败计数清零。dHash 上限限制为 7：8 个 8bit band 的鸽巢保证在 D≤7 内至少有一个 band 完全相同，D=8 时可能每个 band 都差 1 bit 而漏检。
- 成组条件：从候选发现帧到 A 段结束，取 A/B 剩余帧的较短者为分母；只有失败段被后续成功接住时，这段失败帧才从分母扣除；末尾尚未被接住的失败段仍计入分母（短暂特效不判死）。命中比例 ≥ 整组吻合率，连续命中比例 ≥ 连续吻合率，分母至少 6 帧。片头按最多 20 秒设计，20 秒之后还要求至少 3 帧 pHash 低频轮廓一致，避免整段共享片头被误判。两片时长差超过 15 秒或较短片 15% 的对直接跳过。
- 已知限制：片头按不超过 20 秒设计，片头更长时查不出来；片头长度差由「片头容差」限制；完全一致的副本也参与比对，本模块会一并移动，不再排除。
- 不再使用热桶跳过、中段抽样、整段 LCS 对齐或视频级 SimHash；这些方案要么会漏掉共享片头的候选，要么无法定位片头末端。
- 指定文件快速查重：面板里输入一个文件路径，直接查已有缓存，不重扫目录。先按 `band_luma` 召回 MAD 候选，再按 `band_dhash` 召回哈希候选，加载候选 BLOB 后用同一套 LCS 校验；返回候选路径、命中帧数、覆盖率、连续率、偏移。指定文件没有缓存、BLOB 不完整或 luma/dHash 倒排缺失时，会只对这一条视频抓帧并重建索引，然后继续查重；不会报“请先扫描”，也不会偷偷全盘抓帧。它和扫描一样走 `runTask`，状态区会显示「读取指纹 / 生成指纹缓存 / 召回候选 / 已比对 N/M」日志，并可用全局强制停止中断；查询文件自身不会作为重复结果返回。
- 命中整组文件可一键移动：在输出目录下为每个相似组新建子文件夹（重复组_001、重复组_002…），组内保留原文件名；输出目录同样不能等于/位于来源内部，也不能是盘符根目录。
- 复位：五个会移动文件的功能（时长匹配、忽略片头、按大小、按时长、统一编码）都有「复位文件」。移动时写 `_dupfc_restore.json` 记录（抓帧两模块写在各分组目录内，其余写在目标目录根部）；复位按记录把文件搬回各自原目录，已被删除的跳过并计数，原目录不存在会报错、文件留在原处；分组目录/统一编码对比目录里不在记录中的文件会统一 UUID 改名移到该目录下的 `resetFail`。
- 可调参数（界面上都有，默认值即推荐值）：
  - 抓帧时长(秒)：只抓每条视频前 N 秒，默认 40、最大 60；片头按不超过 20 秒设计。
  - 抓帧频率(帧/秒)：每秒抓几帧来比较，默认 2，范围 1–5。
  - 片头容差(秒)：允许第一对匹配帧错开多少秒，默认 10、最多 20；0 = 必须对齐。
  - 失败容忍帧数：候选累计失败多少帧后淘汰，默认 8；越大越宽松但更慢。
  - 失败清零所需连续成功帧数：失败计数只有在之后连续成功这么多帧后才清零，默认 15；越大越严格。
  - 单帧灰度差上限：两帧缩成 16×16 黑白小图后亮度差的平均值上限，默认 15，越小越严格。
  - dHash 差异上限：明暗结构指纹的差异位数上限，默认 4，越小越严格。
  - pHash 差异上限：整体轮廓指纹的差异位数上限，默认 8；只在 MAD 不中时，与 dHash 一起作为哈希兜底。
  - 整组吻合率(%)：候选内容段里命中的比例，默认 90%，调低更容易成组也更易误判。
  - 连续吻合率(%)：还要连续命中的比例，默认 85%，防止零散几帧碰巧相似就拼成组。
